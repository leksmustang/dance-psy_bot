# Прототипы бизнес-ботов

[English version](./README.md)

Набор отраслевых Telegram-прототипов для танцевальной студии, психолога и детейлинга.

Проекты появились до общего Runtime QuickPult и показывают, как реальные процессы услуг переводились в состояния бота, логику записи и внешние интеграции. Репозиторий сохранён как **портфолио и история развития**, а не как готовая production-система.

## Реализованные подходы

- отдельные Telegram-боты на aiogram и python-telegram-bot;
- FSM-сценарии и сохранение пользователей и записей;
- получение свободных слотов и создание событий в Google Calendar;
- пробная запись, состояние оплаты и ограничения переноса;
- отраслевые опросы, меню и квалификация обращений;
- antiflood middleware, слои repository и service;
- SQLite, Docker и асинхронная работа с I/O.

## Архитектура

- `app/bots/` — отраслевые точки входа и обработчики;
- `app/repositories/` — операции с данными;
- `app/services/` — запись, календарь и валидация;
- `app/middlewares/` — общие ограничения, включая antiflood;
- `app/models.py` и `app/database.py` — локальный слой данных.

## Почему проект важен

Поддержка нескольких независимых ботов выявила повторяющиеся части бизнес-автоматизации: идентификация, запись, оплата, передача человеку, транспорт канала и отчётность. Этот опыт стал основанием для общего Runtime и версионируемых конфигураций **[QuickPult](https://quickbizauto.com)**.

## Локальный запуск

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
python run.py
```

Для Google Calendar дополнительно нужен файл сервисного аккаунта. Его и реальные токены ботов нельзя добавлять в Git.

## Текущие границы

- Это ранний портфолио-код с несколькими отраслевыми ботами в одном репозитории.
- Для запуска нужны контент проекта, токены, календарь и инициализация БД.
- Часть сценариев является прототипной и требует проверки перед повторным использованием в production.
- Активное развитие перенесено в единую платформу QuickPult.
